## 1) Problem — Pain Point (verbatim จากโจทย์)

เจ้าของร้านค้าเล็ก **ไม่รู้กำไรสุทธิแต่ละวัน** — จดบัญชีลงสมุดหรือจำเอา
**ข้อมูลหายบ้าง ลืมบ้าง** สิ้นเดือนแล้วก็ยัง **ไม่รู้ว่าเดือนนี้กำไรจริงหรือขาดทุนจริง**

**ทำไมระบบนี้ถึงแก้ปัญหาได้:**
- เก็บทุกบิลไว้ที่เดียว (ไม่หาย ไม่ต้องจำ) + แนบรูปสลิป/ใบเสร็จเป็นหลักฐาน
- **บวก-ลบให้อัตโนมัติ** → เห็น "กำไรสุทธิวันนี้/เดือนนี้" ทันทีโดยไม่ต้องนั่งคิดเลขตอนดึก
- เทียบกับเดือนก่อน + ตั้งงบ/ตั้งเป้า → ตัดสินใจได้ว่าควรคุมรายจ่ายตรงไหน

**ถ้าไม่มีระบบนี้ ผู้ใช้ทำยังไงตอนนี้?** → จดสมุดปกอ่อน/แอปโน้ตในมือถือแล้วมานั่งบวกเองตอนปิดร้าน
หรือไม่จดเลยแล้วใช้ "ความรู้สึก" ว่าวันนี้ขายดี — ซึ่งมักคลาดจากความจริงและทำให้ตัดสินใจผิด

## 2) Persona — ใครใช้ (คนจริง คนเดียว บริบทชัด — ไม่ใช่ "ร้านค้า/แม่ค้า/ทุกคน")

**"พี่นภา" — นภา แซ่ลิ้ม อายุ 43 ปี เจ้าของร้านขายของชำ "ร้านนภาพาณิชย์" ในซอยตลาดนัดย่านบางแค กรุงเทพฯ**

- **เปิดร้านคนเดียว** ตั้งแต่ 6 โมงเช้าถึง 2 ทุ่ม (บางวันลูกสาว ม.ปลาย มาช่วยขายช่วงเย็น)
- ขายของจิปาถะ: ขนม น้ำอัดลม ของใช้ในบ้าน + ทอดกล้วย/ปาท่องโก๋หน้าร้านตอนเช้า
- ขายของหลายอย่าง **ราคาคงที่** (เช่น มาม่าซองละ 6 บาท) → อยากรู้ว่าแต่ละอย่าง **ได้กำไรขั้นต้นกี่ %** คุ้มที่จะขายต่อไหม
- มี **ค่าใช้จ่ายประจำทุกเดือน** (ค่าเช่า ค่าน้ำค่าไฟ ค่าจ้างลูกจ้างพาร์ทไทม์) ที่ **ต้องจดซ้ำทุกเดือน** — น่าเบื่อและลืมง่าย
- รายการซื้อ-ขายวันละ **40–80 บิล** ส่วนใหญ่เป็นเงินสด ยอดต่อบิลหลักสิบถึงร้อยต้นๆ
- ใช้ **มือถือ Android เครื่องเดียว** (จอ ~6 นิ้ว) กรอกขณะมือยังจับของ/ทอนเงิน → ต้องกรอก **เร็ว แตะน้อยครั้ง** และ **ถ่ายรูปสลิป/ใบเสร็จแนบ** จากกล้องในเครื่องได้
- **ไม่ใช่สายเทคโนโลยี:** พิมพ์ไทยช้า, **กลัวกดผิดแล้วข้อมูลหาย**, ไม่เข้าใจศัพท์บัญชี — อยากเห็นแค่ "วันนี้เหลือกำไรเท่าไหร่"
- **เป้าหมายส่วนตัว:** เก็บเงินส่งลูกเรียนมหาวิทยาลัย → อยากตั้ง **เป้ารายได้และค่าใช้จ่าย/เดือน** แล้วเห็นว่าใกล้ถึงเป้าหรือยัง
- เน็ตในร้านบางช่วงหลุด (มุมอับสัญญาณ) → ระบบไม่ควรพังถ้ากดเซฟแล้วเน็ตสะดุด

> **ทำไมเจาะจงคนนี้:** ทุกการตัดสินใจ UX/validation อิงพฤติกรรม "คนกรอกมือถือคนเดียวระหว่างขายของ พิมพ์ช้า กลัวข้อมูลหาย ไม่รู้ศัพท์บัญชี" ของพี่นภา — ไม่ใช่ "ใครก็ได้". ดีไซน์จึงต้องปุ่มใหญ่ ฟอร์มสั้น คีย์เลขเป็นหลัก คำเตือนเป็นภาษาคนทั่วไป.

**Secondary user (รอง):** *ลูกสาวพี่นภา* มาช่วยขายช่วงเย็น บันทึกแทนแม่ได้ — MVP เป็น **single-account** (ใช้บัญชีเดียวกัน), ยังไม่ทำ role-based.

## 3) Goals — สิ่งที่ผู้ใช้ต้องทำได้สำเร็จ

1. บันทึกรายรับ/รายจ่ายแต่ละบิลได้ใน **ไม่กี่วินาที** + เลือกหมวด + แนบรูปสลิป
2. เปิดมาก็เห็น **กำไรสุทธิวันนี้** และ **กำไรสุทธิเดือนนี้** ทันที (เทียบเดือนก่อน)
3. ตั้ง **งบรายหมวด** + ถูกเตือนเมื่อใช้เกินงบ
4. ตั้ง **เป้ารายได้/รายจ่ายต่อเดือน** + เห็นความคืบหน้าเป็น %
5. ตั้ง **ต้นทุน/ราคาขายต่อสินค้า** → รู้ **อัตรากำไรขั้นต้น %** ทันที + เตือนเมื่อต่ำกว่าเกณฑ์
6. ตั้ง **ค่าใช้จ่ายประจำ** ให้สร้างอัตโนมัติทุกเดือน + ข้ามได้เฉพาะเดือนที่ไม่เกิด
7. **แก้รายการย้อนหลังได้** โดยมีประวัติการแก้ + เหตุผล + กระทบยอดกับใบเสร็จที่แนบ
8. เชื่อใจตัวเลข: ระบบ **กันกรอกผิด/กรอกซ้ำ** และไม่ทำข้อมูลหาย

## 4) Primary flow — เส้นทางหลัก (พี่นภา ใช้จริงครบลูป)

1. **Register → Login** (email + password) ครั้งแรก → เข้าหน้าหลัก (per-user: เห็นเฉพาะข้อมูลร้านตัวเอง)
2. หน้าหลัก **Today**: เห็นกำไรสุทธิวันนี้ + ปุ่มใหญ่ "+ บันทึกรายการ"
3. กด **บันทึก**: เลือก รายรับ/รายจ่าย → ใส่จำนวนเงิน (คีย์เลข) → เลือกหมวด → (ถ่าย/แนบรูปสลิป) → บันทึก
   - ถ้ากรอกซ้ำ (วันที่+จำนวน+หมวดเดียวกัน) หรือยอดสูงผิดปกติ → **เตือน ยืนยันก่อนบันทึก**
4. ดู **หน้าสรุปรายหมวด**: ใช้ไปเท่าไร / งบเท่าไร / เกินงบไหม (alert)
5. ดู **หน้ากำไร**: รายวัน / รายเดือน / เทียบเดือนก่อน (▲▼ %)
6. ตั้ง **เป้า** (รายได้+รายจ่าย) → เห็น progress %
7. ตั้ง **ต้นทุนสินค้า** (เช่น มาม่า) → เห็น margin %
8. ตั้ง **ค่าใช้จ่ายประจำ** (ค่าเช่า) → เดือนถัดไปขึ้นอัตโนมัติ; เดือนไหนไม่จ่ายก็กดข้าม
9. เผลอกรอกผิด → **แก้ + ใส่เหตุผล** → ดูประวัติการแก้ได้
10. **Logout** → กลับมา Login ใหม่เห็นข้อมูลเดิมครบ

## 6) Definition of Done (5 ข้อจากโจทย์ — ทุกข้อต้อง demo ได้ด้วยตัวเลขเป๊ะ)

1. **DoD-1** บันทึก 'ค่าหน้าร้าน 2,000 บาท' + หมวด 'ค่าใช้จ่าย' + **แนบรูปใบเสร็จ** → บันทึกสำเร็จ + เปิดดูรูปที่แนบได้
2. **DoD-2** หน้าสรุปรายหมวด → 'ค่าใช้จ่าย' ใช้ไป 5,000 จากงบ 8,000 บาท **พร้อม alert เกินงบ/ใกล้เกิน**
3. **DoD-3** หน้ากำไร → รายวัน +300 / รายเดือน +8,500 เทียบเดือนก่อน +6,200 (เห็นทิศทาง ▲▼)
4. **DoD-4** ตั้งเป้ารายได้ 20,000/เดือน → เห็นความคืบหน้า **65%** ณ กลางเดือน
5. **DoD-5** ตั้งต้นทุนมาม่า 3 บาท ราคาขาย 6 บาท → **อัตรากำไรขั้นต้น 50%** แสดงทันที

## 7) Edge Cases (จากโจทย์ — ต้องรองรับครบทั้ง 4)

1. **EDGE-1 — แก้รายการย้อนหลัง** → แก้ได้ แต่ **บันทึกประวัติทุกการเปลี่ยนแปลง + บังคับระบุเหตุผล**
2. **EDGE-2 — กด submit ซ้ำสองครั้ง** → **ตรวจรายการซ้ำ (วันที่+จำนวน+หมวดเดียวกัน) → เตือนยืนยันก่อนบันทึก**
3. **EDGE-3 — ค่าใช้จ่ายประจำเดือนนี้ไม่เกิด** (เช่น ยกเว้นค่าเช่า) → **ข้ามเฉพาะเดือนนั้น ไม่ลบรูปแบบรายการประจำ**
4. **EDGE-4 — บันทึกตัวเลขผิด** (เช่น 10,000 แทน 1,000) → **เตือนถ้าสูงผิดปกติจากค่าเฉลี่ย → ยืนยันก่อนบันทึก**

### Proactive edge cases (เพิ่มเอง — ตามพฤติกรรมพี่นภา; ตรวจที่ AUTH-* และ Output Quality)
> เหล่านี้คือ "ของแถม" ที่ทำให้ Output Quality + Business Understanding ขึ้น level 4 — ระบุเองโดยไม่ต้องถูกถาม:
- **กรอกเลขเพี้ยน:** ตัวอักษร/ค่าว่าง/0/ติดลบ/ทศนิยมเกิน 2 ตำแหน่ง → บล็อก + **ข้อความไทยเจาะจง** (ไม่ใช่ raw error)
- **เพดานจำนวนเงิน:** กันพิมพ์ยาวเกินจริง (เช่น เกิน 10,000,000) → เตือน
- **วันที่อนาคต:** เลือกวันที่ยังมาไม่ถึง → เตือน/บล็อกตามนิยาม
- **หน้าว่าง (empty state):** ยังไม่มีข้อมูล → แสดงสถานะว่าง + ชวนเริ่มบันทึก (ไม่โชว์ NaN/กราฟพัง)
- **หารด้วยศูนย์:** เป้า/งบ = 0 หรือยังไม่ตั้ง → progress/margin ไม่ NaN (clamp/กันหาร 0)
- **ขาดทุน:** กำไรติดลบ → แสดงสีแดง + เครื่องหมายชัด (พี่นภาต้องเห็นทันทีว่าวันนี้ขาดทุน)
- **เน็ตหลุดตอนเซฟ:** บันทึกล้มเหลว → ไม่ทำข้อมูลหายเงียบ ๆ, แจ้งให้ลองใหม่ (ค่าที่กรอกยังอยู่)
- **เขตเวลา:** ตัดยอด "วันนี้/เดือนนี้" ตามเวลาไทย (Asia/Bangkok) ไม่ใช่ UTC → กันยอดข้ามวันเพี้ยน
- **ลบรายการสุดท้ายของวัน/เดือน:** สรุปกลับเป็น empty state ถูกต้อง ไม่ค้างตัวเลขเก่า
- **margin ต่ำ/ติดลบ:** ขายต่ำกว่าทุน → เตือนชัด (F5 เกณฑ์)

## 8) AUTH (บังคับ — ใช้งานได้ครบลูปตั้งแต่ register/login)

- **AUTH-1** Register ด้วย email+password → สร้างบัญชีและเข้าระบบได้
- **AUTH-2** Login ด้วย email+password ถูกต้อง → เข้าหน้าหลัก; ผิด → ข้อความไทยเจาะจง (ไม่ใช่ raw 500)
- **AUTH-3** **Per-user data isolation** — ผู้ใช้ A เห็นเฉพาะข้อมูลร้านตัวเอง ไม่เห็นของผู้ใช้ B (ข้อมูลผูก `user.id` ทุก query)
- **AUTH-4** Logout → ออกจากระบบ; กลับเข้ามาใหม่เห็นข้อมูลเดิมครบ
- **AUTH-5** Protected-route redirect — ยังไม่ login แล้วเปิดหน้าในแอป → เด้งไปหน้า login

## 9) Out-of-scope — ไม่ทำใน MVP นี้ (ป้องกัน scope creep → คุม Time)

- Multi-store / หลายสาขา, ระบบสต๊อก/คงคลังเต็มรูป (F5 เก็บแค่ ต้นทุน/ราคาต่อสินค้า เพื่อคิด margin — ไม่ track จำนวนคงเหลือ)
- Role-based permissions (admin/staff/viewer) → MVP เป็น single-account
- แอป native / offline-sync เต็มรูป (รับแค่ให้ "เซฟล้มเหลวแล้วไม่หาย")
- ระบบบัญชี double-entry, ใบกำกับภาษีเต็มรูป (N3 ทำแค่คิด VAT ต่อรายการ + สรุปภาษีขายรายเดือน)
