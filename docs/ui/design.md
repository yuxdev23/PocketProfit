# UI / UX Design — yu-expenses (โจทย์ 02)

> Build-ready spec สำหรับ **app-dev**. Persona = **พี่นภา 43 ปี ร้านชำคนเดียว มือถือ Android จอ ~6", พิมพ์ช้า กลัวข้อมูลหาย ไม่รู้ศัพท์บัญชี**.
> หลักการ: **mobile-first** (375 → 768 → 1280), ปุ่มใหญ่ (≥44px tap), ฟอร์มสั้น, คีย์เลขเป็นหลัก, คำเตือนภาษาคนทั่วไป, **ตัวเลขห้าม NaN/พัง**, ขาดทุน/เกินงบเห็นทันที (สีแดง + ▼).
> Stack: Next.js 15 App Router · shadcn/ui (new-york) · Tailwind v3 · react-hook-form + zod · recharts · sonner · date-fns. **Timezone ทุกอย่าง = Asia/Bangkok**.
> **Validation messages = ของจริง พิมพ์ตามคำต่อคำ** (§4). นี่คือจุดเก็บแต้ม Output Quality (20%).

## 2) Add-Entry Form — หัวใจของแอป (F1, EDGE-2, EDGE-4, DoD-1, N3)

เปิดเป็น **Dialog** (มือถือ = เต็มจอเกือบหมด). เปิดจาก FAB ทุกหน้า. Component = `AddEntryDialog`.

**ลำดับ field (เรียงตามความเร็วการกรอก — เลขก่อน):**

1. **ประเภท** — `Tabs` 2 ปุ่มใหญ่เต็มความกว้าง: **[ รายรับ ]** (เขียว) / **[ รายจ่าย ]** (แดง). default = รายจ่าย (พี่นภาจ่ายบ่อยกว่า). → ตั้งสี accent ของฟอร์มตามที่เลือก.
2. **จำนวนเงิน (บาท)** — `Input` `inputMode="decimal"` ตัวเลขใหญ่ (text-2xl) **autofocus**. ขึ้นคีย์บอร์ดเลขทันที.
3. **หมวด** — `Select` (รายรับ→หมวดรายรับ, รายจ่าย→หมวดรายจ่าย). มีปุ่ม "+ หมวดใหม่" ท้ายลิสต์ (ถ้าทำ N2).
4. **วันที่** — default = **วันนี้ (Asia/Bangkok)**. `Input type="date"` (native picker เร็วบนมือถือ). max = วันนี้.
5. **แนบรูปสลิป (ไม่บังคับ)** — `Input type="file" accept="image/*" capture="environment"` → ปุ่ม "📷 ถ่าย/แนบรูป" → preview thumbnail + ปุ่มลบ.
6. **VAT 7% (ไม่บังคับ, N3)** — `Switch`/checkbox "มี VAT 7%"; เปิด → โชว์ "ก่อน VAT / VAT / รวม" คำนวณสด.
7. **หมายเหตุ (ไม่บังคับ)** — `Input` สั้น.

**ปุ่มท้าย:** `[ ยกเลิก ]` (ghost) · **`[ บันทึก ]`** (เต็มความกว้าง, สูง, `bg-accent-brand`). ระหว่างบันทึก → spinner + ข้อความ "กำลังบันทึก…" (ปุ่ม disabled กันกดซ้ำ = EDGE-2 ชั้นแรก).

**Confirm interstitial (EDGE-2 + EDGE-4):** ถ้า submit แล้ว server ตอบว่า *ซ้ำ* หรือ *สูงผิดปกติ* → **ไม่บันทึกทันที** แต่เปิด `AlertDialog`/Dialog ยืนยัน (ดู §4 D) พร้อมปุ่ม "ยืนยันบันทึก" / "แก้ไขก่อน". ค่าที่กรอก**ยังอยู่ในฟอร์มเสมอ** (กันข้อมูลหาย).

**สำเร็จ:** ปิด dialog → `toast.success` เขียว "บันทึกรายการแล้ว" → รายการใหม่ขึ้นบนสุดของลิสต์ (optimistic หรือ refresh).

## 3) States — empty / loading / error (ทุก list & fetch)

> กฎ: **ห้ามโชว์ NaN, กราฟพัง, หรือ 0/0**. ทุกหน้าที่ดึงข้อมูลต้องมี 3 สถานะนี้.

| หน้า/ส่วน | Empty | Loading | Error |
|-----------|-------|---------|-------|
| Today — ลิสต์วันนี้ | ไอคอน + "วันนี้ยังไม่มีรายการ — แตะ + เพื่อบันทึกบิลแรก" + ปุ่มใหญ่ | `Skeleton` 3 แถว + การ์ดตัวเลข skeleton | การ์ด "โหลดข้อมูลไม่สำเร็จ ลองใหม่อีกครั้ง" + ปุ่มลองใหม่ |
| Today — กำไรสุทธิ | แสดง **฿0** (ไม่ใช่ว่าง/NaN) | skeleton ตัวเลข | "—" + ข้อความ error เล็ก |
| /entries | "ยังไม่มีรายการในช่วงที่เลือก" + ปุ่มล้างตัวกรอง | `Skeleton` table 5 แถว | การ์ด error + ลองใหม่ |
| /budgets | "ยังไม่ได้ตั้งงบรายหมวด — ตั้งงบเพื่อรับการเตือนเมื่อใช้เกิน" + ปุ่มตั้งงบ | skeleton การ์ดหมวด | error card |
| /profit | กราฟ → "ยังไม่มีข้อมูลพอแสดงกราฟ"; ตัวเลข = **฿0 / 0%** (clamp) | skeleton ตัวเลข + กราฟ | error card |
| /goals | "ยังไม่ได้ตั้งเป้าเดือนนี้" + ปุ่มตั้งเป้า; ถ้าเป้า=0 → progress **0%** ไม่ใช่ NaN | skeleton | error card |
| /products | "ยังไม่มีสินค้า — เพิ่มสินค้าเพื่อดูกำไรขั้นต้น %" | skeleton list | error card |
| /recurring | "ยังไม่มีค่าใช้จ่ายประจำ — ตั้งค่าเช่า/ค่าน้ำค่าไฟให้ขึ้นอัตโนมัติทุกเดือน" | skeleton | error card |

**Save/network failure (เน็ตหลุด — proactive edge):** mutation ล้มเหลว → `toast.error` "บันทึกไม่สำเร็จ ลองอีกครั้ง — ข้อมูลที่กรอกยังอยู่" + ฟอร์ม**ไม่ปิด ไม่ล้างค่า**.
**ลบรายการสุดท้ายของวัน/เดือน:** สรุปต้องกลับเป็น empty state ถูกต้อง (revalidate) ไม่ค้างตัวเลขเก่า.
**ขาดทุน:** กำไรสุทธิ < 0 → ตัวเลขสีแดง (`text-expense`) + เครื่องหมาย "−" + ▼ ชัดเจน.

## 4) Validation rules + **ข้อความไทยเป๊ะ** (พิมพ์ตามคำต่อคำ)

> ใช้ **zod schema เดียวกันทั้ง client & server** (Output Quality + ความปลอดภัย). client = react-hook-form + zodResolver; server = re-validate ก่อนเขียน DB. ทุกข้อความขึ้นใต้ field (`FormMessage`) ยกเว้น toast/AlertDialog ที่ระบุ.

### A. ฟอร์มบันทึกรายการ (add/edit entry)

| field | rule | ข้อความไทย (verbatim) |
|-------|------|------------------------|
| จำนวนเงิน | required / ว่าง | `กรุณากรอกจำนวนเงิน` |
| จำนวนเงิน | ไม่ใช่ตัวเลข (มีตัวอักษร) | `กรอกเป็นตัวเลขเท่านั้น` |
| จำนวนเงิน | ≤ 0 หรือ ติดลบ | `จำนวนเงินต้องมากกว่า 0 บาท` |
| จำนวนเงิน | ทศนิยม > 2 ตำแหน่ง | `จำนวนเงินใส่ทศนิยมได้ไม่เกิน 2 ตำแหน่ง` |
| จำนวนเงิน | > 10,000,000 | `จำนวนเงินสูงเกินไป กรุณาตรวจสอบอีกครั้ง` |
| หมวด | ไม่ได้เลือก | `กรุณาเลือกหมวดก่อนบันทึก` |
| ประเภท | ไม่ได้เลือก (กันพลาด) | `กรุณาเลือกประเภทรายรับหรือรายจ่าย` |
| วันที่ | อนาคต (> วันนี้ Asia/Bangkok) | `เลือกวันที่ในอนาคตไม่ได้` |
| วันที่ | รูปแบบผิด/ว่าง | `กรุณาเลือกวันที่ให้ถูกต้อง` |
| รูปแนบ | ไฟล์ไม่ใช่รูป | `แนบได้เฉพาะไฟล์รูปภาพ` |
| รูปแนบ | > 5 MB | `รูปใหญ่เกินไป (ไม่เกิน 5 MB)` |

### E. Auth (AUTH-1, AUTH-2)
| ที่ | rule | ข้อความไทย |
|----|------|-----------|
| email | รูปแบบผิด/ว่าง | `กรุณากรอกอีเมลให้ถูกต้อง` |
| password | < 8 ตัว | `รหัสผ่านต้องมีอย่างน้อย 8 ตัวอักษร` |
| login ผิด | (AUTH-2) | `อีเมลหรือรหัสผ่านไม่ถูกต้อง` |
| signup email ซ้ำ | (AUTH-1) | `อีเมลนี้ถูกใช้สมัครแล้ว` |
| network/500 | ทุก mutation | `เกิดข้อผิดพลาด กรุณาลองใหม่อีกครั้ง` (toast — **ห้ามโชว์ raw 500**) |

### F. Number/divide-by-zero guards (proactive — ใส่ใน util ทุกที่)
- progress% = `total === 0 ? 0 : Math.min(100, Math.round(actual/total*100))` → clamp 0–100, ไม่ NaN.
- margin% = `price <= 0 ? 0 : Math.round((price-cost)/price*100)`.
- เทียบเดือนก่อน: เดือนก่อน=0 → แสดง `—` หรือ "ไม่มีข้อมูลเดือนก่อน" แทน `Infinity%`.
- ทุกตัวเลขเงินแสดงด้วย `Intl.NumberFormat('th-TH')` + "฿" / " บาท".

## 7) สรุปจุดเก็บแต้มสำหรับ app-dev (อย่าพลาด)
1. **Validation §4 = พิมพ์ตามคำต่อคำ** — client+server zod ตัวเดียวกัน. ห้าม raw 500 (→ toast §4 E/F).
2. **ทุก list/fetch ต้องมี empty + loading(skeleton) + error** (§3). ห้าม NaN/กราฟพัง/0÷0 (§4 F).
3. **EDGE 1–4 ครบ:** เหตุผลแก้, ยืนยันซ้ำ, ยืนยันยอดสูง, ข้ามประจำเฉพาะเดือน.
4. **ขาดทุน/เกินงบ/margin ต่ำ = เห็นทันที** (สีแดง + ▲▼ + เครื่องหมาย, ไม่พึ่งสีอย่างเดียว).
5. **Asia/Bangkok** ทุกการตัดยอดวัน/เดือน. **per-user (AUTH-3)** ทุก query.
6. **เซฟล้มเหลว = ค่าที่กรอกไม่หาย** (ฟอร์มไม่ปิด/ไม่ล้าง).
7. Tokens = **ใช้ utility ที่มีอยู่** (§5) ห้าม hardcode สี. add แค่ 3 component (§6).
